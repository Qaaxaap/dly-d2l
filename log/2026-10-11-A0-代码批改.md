## 讲了什么

批改过程中发现三处**讲义的责任**，当场补了讲义，不计入学习者的错：

1. **§4.4 没说 `reshape` 返回新张量。** 只写了"把 12 个元素排成 3 行 4 列"，
   学习者照抄 `x.reshape((3, 4))` 单独一行，原张量没变。已补：`reshape` 返回新张量，
   并列出 `reshape` / `.to()` / `.cpu()` / `.numpy()` / `.clone()` 这一组"返回新对象"的方法。
2. **§4.7 的 API 示例写的是 `plt.savefig("out.png", ...)`**，而任务要求存到
   `work/a0/sin.png`。示例本身就是诱导，学习者照写必然错。已把示例改成占位符
   `"文件名.png"`，并加一段说明 savefig 的路径相对命令所在目录（仓库根）。
3. **§4.7 说"matplotlib 只认 numpy 数组，不认 torch 张量"，这句是错的。**
   本机实测（matplotlib 3.11.2）：CPU 张量可以直接画，matplotlib 内部自己转 numpy；
   显卡张量才会报 `can't convert cuda:0 device type tensor to numpy`。
   已改成对照表，规则重述为"传进去的东西必须在 CPU 上"。

顺带讲了两条：

- **"哪份张量在哪"**：`g = x.to("cuda")` 之后张量有两份，`x` 在 CPU、`g` 在显卡，
  对谁做运算就在谁上面算。学习者在 `x = x * 2` 里算的是 CPU 那份。
- **断言之间不能互相污染**：`sin.png` 是上一轮留下的旧文件时，路径写错也能蒙混过关。
  `check_a0.py` 的 T10/T11 已改成要求"本次运行必须更新过这个文件"。
